# 定位工作流与验收

## 操作顺序

1. 确认目标设备及期望坐标；只操作自己或明确获准操作的设备。
2. 用 USB 连接并解锁手机，在手机上完成信任和开发者模式确认。
3. 在独立 Python 环境安装固定依赖，列出设备并明确指定 UDID。
4. 加载开发支持组件。成功加载与成功改变定位是两个不同的检查点。
5. 开启异步持续模拟。保持终端、USB 连接和电脑唤醒。
6. 用户在地图点击「我的位置」，核对蓝点旁的道路或建筑，确认位置持续保持。
7. 请求恢复时，先停止持续更新，在原连接清除并等待 3 秒；关闭原连接，再建立新连接单独清除并等待 3 秒。整个过程持有会话锁，第二次调用结束前不报告流程完成。
8. 用户重新打开地图并核对真实位置。未确认前，记录为「恢复待验证」。

## 排查顺序

| 现象 | 下一步 |
| --- | --- |
| 找不到手机 | 检查数据线、解锁、信任提示及设备列表 |
| 开发者模式关闭 | 在手机开启并重启，再次解锁确认 |
| Xcode 无法挂载开发镜像 | 检查 Xcode 与 iOS 的兼容性；尝试固定版本工具的 auto-mount |
| 指令成功，地图仍在原处 | 点击「我的位置」；检查持续进程是否仍在运行；关闭其他模拟工具 |
| 已在目标城市，但有几百米偏差 | 核对经纬度顺序和 WGS84 / GCJ-02 / BD-09 坐标系 |
| 短暂到达后返回原处 | 检查连接是否断开或被另一调试连接替换；保持异步事件循环 |
| 恢复指令后地图仍不变 | 先确认没有持续更新进程，再用 clear；重开地图等待真实定位 |

## 证据边界

- 终端确认的是调用或传输状态，不是手机地图的显示状态。
- 地图显示目标地址的搜索标记，不代表当前位置已改变。需要看当前位置蓝点。
- 记录「用户确认稳定到达」和「用户确认恢复」，不把某次命令的退出码扩展成全机型支持。
- 2026-10-29 的用户确认来自本工作流原型。公开版将同一机制参数化，并增加文件锁、输入校验与停止控制；自动测试只证明覆盖到的程序行为。
- 原型中一次性命令未稳定生效；持续异步更新后用户确认稳定。阻塞等待是可能原因，未完成独立因果验证。
- 清除后保留连接的原型经过用户确认恢复。网络和设备状态会变化，公开版每次恢复仍要求人工确认。
- 2026-10-29 的公开版恢复复测中，首次 `stop` 后用户报告尚未恢复；随后独立 `clear` 后用户确认恢复。修复版自动执行这次独立调用，即使第一次返回成功也不跳过。无法据此确定具体的系统内部原因。
- 修复验证将自动化回归测试与实机检查分开记录。仅连续执行清除命令可以检查新连接是否能正常调用，不等同于重新开启模拟再停止的完整实机验收。

## 公开内容边界

只发布通用脚本、文档、测试和许可证。真实设备 UDID、序列号、用户名路径、截图、位置历史、配对文件、凭证及开发镜像不属于公开材料。
